# SmartClean-Sim 后续实施路线

## 已完成基线

### P0：确定性二维闭环

- 中文任务解析、垃圾目标、A*、危险区、动态障碍、清扫、返航和指标。
- CLI、配置、自动测试、架构和接口文档。

### P1：覆盖与展示

- 命名栅格区域与 `clean_area` 全覆盖模式。
- 横向/纵向蛇形候选和 A* 区段连接。
- 与动态障碍同步的逐帧仿真快照。
- 无外部依赖的自包含 HTML/Canvas 动画。

### P1.5：ROS 2 环境与回放桥

- 锁定仓库内 ROS 2 Humble Desktop、Nav2、SLAM Toolbox 和 Gazebo Fortress 桥环境。
- 建立独立 `ros2_ws/`，保持二维核心零 ROS 依赖。
- 发布状态 JSON、完整 `nav_msgs/Path` 和逐帧 `PoseStamped`。
- 完成格坐标到右手米制 `map` 坐标转换、colcon 测试和 Topic 端到端探针。
- 增加无在线资源依赖的 Gazebo Fortress 最小环卫 World，并自动验证 ROS `/clock` 桥接。
- 提供 Ubuntu 22.04 / Humble 官方容器蓝图；当前代理会话因 Docker daemon 权限未完成镜像构建。

### P4-M1：Gazebo 差速底盘最小闭环

- 建立仓库内 `smartclean_robot` SDF 模型、碰撞/惯性、左右驱动轮与万向支撑轮。
- 使用 Gazebo Fortress DiffDrive 接入标准 ROS2 `/cmd_vel`，回传 `/odom` 与 `odom -> base_link` TF。
- 在控制入口增加独立安全看门狗：0.5 秒断流、NaN/Inf 或异常时持续输出零速度。
- 自动验证前进、原地转向、里程计、TF、仿真时钟、断流停车和 World 服务。
- 模型与 World 全部使用仓库内资源，不依赖 Gazebo Fuel 在线下载。

## 后续优先级

### P2：场景与实验体系

目标：从“一个 Demo”扩展成可重复的对比实验。

- 增加道路、停车场、狭窄通道、积水密集区和多行人场景。
- 增加批量实验入口、场景 ID、配置哈希和 CSV 汇总。
- 对比定点清扫与全覆盖的路径长度、覆盖率、重规划和完成率。
- 为比赛报告生成可追溯表格和图。

验收：至少 5 个固定场景、每个场景可重复运行、失败原因结构化、汇总结果能关联 Git commit 和配置。

### P3：感知闭环

目标：用真实图片或视频替换场景中的垃圾真值输入。

- 建立垃圾类别、数据集卡和标注规范。
- 接入轻量 YOLO/ONNX 推理适配器，同时保留 `MockPerception`。
- 设计像素框到地图位置的投影或仿真真值对齐方法。
- 分开报告检测准确率和二维任务完成率。

验收：固定小测试集、可复现推理命令、检测输出符合统一契约；无 GPU 时核心测试仍通过。

### P4：ROS2 与 Gazebo

目标：把核心算法接入机器人通信和三维仿真。

- 已完成版本决策、独立工作空间、基础桥接节点、可复现环境和 Gazebo `/clock` 冒烟。
- 已完成 Gazebo 差速机器人、`/cmd_vel`、`/odom`、基础 TF 和断流安全停车。
- 下一里程碑 P4-M2：增加 LiDAR `/scan`、传感器坐标系与完整 `map -> odom -> base_link` TF 链。
- 随后接入 Nav2 最小导航，再增加相机和清扫 Action。
- 再评估 Nav2 与 OpenNav Coverage，而不是复制第二套状态机。

最终验收：一条 launch 命令启动、可取消任务、动态障碍时安全停车或重规划、CLI 基线不回归。当前达到 P4-M1“底盘运动闭环”，尚未达到 Nav2 自主导航、任务 Action 或完整 P4 验收，不得提前宣称完成 P4。

### P5：LLM、Web 与 RDK

- LLM 只生成受 Schema 校验的候选任务，非法输出必须拒绝或降级。
- Web 面板提供开始、暂停、返航、任务输入和状态回放。
- PC 模型导出 ONNX，完成量化、BPU 转换和 RDK 推理适配。
- 有开发板后记录精度、时延、吞吐、温度和资源占用；无板时只表述为适配设计。

## 比赛材料并行线

代码推进的同时持续维护：技术方案、架构图、指标定义、实验表格、2–5 分钟演示视频、答辩讲稿和风险边界。所有指标必须区分“目标值”“二维仿真”“Gazebo”“板端”和“实车”。
