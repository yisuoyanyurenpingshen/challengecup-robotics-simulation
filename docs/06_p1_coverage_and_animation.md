# P1 全覆盖清扫与动画设计

## 目标

P1 在不破坏原有定点垃圾清扫的前提下增加两项可展示能力：

1. 对指定区域的全部安全可通行栅格进行确定性覆盖。
2. 导出与仿真时钟严格同步的自包含 HTML 动画。

## 任务模式

- `clean_spots`：按垃圾类别优先级依次访问目标，保持 P0 行为。
- `clean_area`：先处理已知垃圾，再覆盖指定区域的全部安全可通行格，最后按配置返航。

只有明确出现“全覆盖”“覆盖清扫”“全面清扫”等词组时，规则解析器才选择 `clean_area`。普通“清扫教学楼门口”继续解释为 `clean_spots`。

## 覆盖规划

命名区域由场景配置中的显式栅格集合定义。规划器分别生成横向和纵向蛇形候选顺序，用已有四邻域 A* 连接不连续区段，并确定性选择较短的合法路径。

约束：

- 不进入静态障碍或任务要求避开的危险区。
- 输出相邻点的曼哈顿距离恒为 1。
- 同一输入必须得到完全相同的路径。
- 区域中存在静态不可达格时明确失败，不能静默把它从覆盖分母删除。
- 当前目标是可解释的基础覆盖，不宣称全局最短或工业级最优。

`clean_area` 的覆盖率定义为：

```text
任务区域内已访问的安全可通行格数 / 任务区域安全可通行格总数
```

返航时访问的区域外格子不增加该指标。

## 仿真轨迹快照

动画不能用轨迹数组下标代替仿真时间，因为重规划等待会增加仿真步但不会产生移动。每次运行输出完整 `SimulationFrame`：

- `frame_index`：动画帧序号。
- `sim_step`：离散仿真时钟。
- `state`、`action`：当前状态和帧动作。
- `robot_position`：机器人坐标。
- `dynamic_obstacles`：本仿真步所有动态障碍快照。
- `remaining_trash_ids`、`cleaned_ids`：可随机跳转的完整清扫状态。
- `cleaned_this_frame`、`events`：本帧变化和说明。

移动、等待、清扫、状态转换和结束都会记录。清扫帧与到达帧可以共享同一 `sim_step`，但 `frame_index` 不同。

## HTML 安全和可移植性

- 场景与结果先规范化为 JSON，再安全嵌入 `<script type="application/json">`。
- 必须转义 `<`、`>`、`&`，防止场景名称中的 `</script>` 逃逸数据块。
- 动态文本使用 `textContent`，不拼接为 `innerHTML`。
- 文件不包含外链、CDN 或 `fetch`，可以离线通过 `file://` 打开。
- CLI 只生成文件，不自动打开浏览器。

## 验收

- 全覆盖路径连续、避障、确定且覆盖率达到 `1.0`。
- 等待帧机器人位置不变、`sim_step` 增加。
- 动态障碍位置与同一 `sim_step` 一致，机器人不占用其格子。
- 清扫帧中目标恰好消失。
- 连续两次运行的结果和动画数据完全一致。
- HTML 无外部资源，可由浏览器离线打开。
